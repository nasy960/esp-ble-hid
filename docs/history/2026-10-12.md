## B의 이름 조회/암호화 순서 경쟁으로 재접속 반복

- 관측: B가 15ms로 연결된 직후 이름 조회를 시작하지만 약 70ms 뒤
  `authentication preceded OS identification; reconnect required`와 연결 종료가 반복됐습니다.
  이 로그는 인증 이벤트가 이름 응답보다 먼저 왔다는 뜻이며, 기존 메시지는 이벤트의 실패/성공을
  구분하지 않아 이름 조회 미완료만으로 종료했습니다. 7.5ms 요청 이전 단계의 문제입니다.
- 원인 경로: B OS 미선택 시 키 저장 콜백이 ENOENT를 반환합니다. PC가 이름 응답 전에
  LTK를 요청하면 SDK가 키 없음으로 응답할 수 있습니다. 단순히 ENC_CHANGE에서 기다리는
  것만으로는 이미 전송한 부정 응답을 되돌릴 수 없어 LTK 요청 처리 순서도 수정했습니다.
- 수정: 확인된 B 노트북 연결만 이름 조회 동안 LTK 요청 이벤트를 복사해 보관합니다.
  이름으로 OS가 선택되면 SDK 원래 처리기로 한 번만 넘깁니다. 이름 조회의 기존 2초 제한,
  연결 종료, BLE 호스트 리셋 시 보관 요청을 폐기하며 다른 연결의 키 요청은 그대로 통과합니다.
  인증 이벤트가 먼저 오면 상태 코드를 기록하고 이름 조회 완료까지 입력 준비 상태로 만들지 않습니다.
  먼저 성공한 인증도 이름 응답 후 저장된 키/등록 조건을 다시 검사합니다.
- 구현: ESP-IDF v6.1의 내부 `ble_sm_ltk_req_rx`를 링크 래퍼로 연결했습니다. SDK 파일은
  수정하지 않았으며 링크 맵에서 `ble_hs_hci_evt.c.obj`가 래퍼를 참조함을 확인했습니다.
  SDK 업그레이드 시 내부 함수 시그니처와 호출 경로를 재검증해야 합니다.
- 검증: 이벤트 버퍼 복사, 중복 요청/재생 방지, A 통과, 연결 취소·리셋,
  조기 인증 실패 후 이름 응답, 조기 성공 후 재검증 및 기존 BLE 회귀 테스트 통과.
  ESP-IDF v6.1 빌드 통과. 장치 업로드 및 실제 재접속 검증은 아직 수행하지 않았습니다.
- 확인: `early LTK request deferred` → 이름/OS 선택 → `deferred LTK request resumed`
  → `bonded and encrypted` 순서가 나오는지 확인합니다. PC가 암호화 절차 도중 ATT 이름 응답을
  보내지 않거나 먼저 연결을 종료하면 이 방법만으로 해결되지 않을 수 있습니다. 그 경우
  조회 시간 초과를 포함한 로그로 확인해야 하며 다른 OS의 키를 추측해서 시도하지 않습니다.
- 적용: 페어링 삭제 없이 새 펌웨어를 올리고 B를 재접속합니다. 위 10월 7일 기록의
  '인증이 이름 조회보다 먼저 완료되면 즉시 연결 종료' 동작은 이 수정으로 대체합니다.

```sh
cc -std=c11 -Wall -Wextra -Werror -fsanitize=address,undefined -g \
  -I test/tests/stubs -I test/main test/tests/test_b_auth_gate.c -o /tmp/test-b-auth-gate
ASAN_OPTIONS=detect_leaks=0 /tmp/test-b-auth-gate
```

## 저장된 B 키의 제한적 순차 인증

- 관측: 이전 LTK 대기 방식에서 이름 응답이 계속 시간 초과됐습니다. 인증 전에 이름을
  알아야 한다는 조건 때문에 두 OS의 키가 저장돼 있어도 재접속하지 못했습니다.
- 수정: 기존 등록 재접속은 이름 조회 없이 후보 키를 먼저 선택하고 즉시 인증합니다.
  마지막 성공 후보를 NVS `last_ok`에 저장하며, 없으면 Ubuntu 키부터 존재 여부를 확인합니다.
  인증 후 이름을 읽되 이름 실패/변경으로 키를 바꾸거나 정상 연결을 끊지 않습니다.
- 후보 전환: 실제 OUR_SEC 키를 조회한 연결에서 HCI Authentication Failure(0x205),
  PIN/Key Missing(0x206), MIC Failure(0x23d)를 받으면 해당 후보만 실패로 표시합니다.
  ENC_CHANGE와 DISCONNECT의 중복 오류는 한 번만 반영합니다. 다음 재접속 때 다른 후보를
  사용하며, 두 후보가 모두 실패하면 더 이상 키로 인증하지 않습니다. 인증 성공 시 실패 기록을
  초기화합니다. `os retry` 또는 보드 재부팅으로 시도를 재개할 수 있으며 키는 삭제하지 않습니다.
- 보존: 등록 창 밖에서 키 교체/삭제 금지를 유지합니다. A 저장 경로 및 7.5ms 요청도 유지합니다.
  `pair b` 신규 등록은 이름으로 저장 영역을 고르는 기존 경로를 사용하므로 이름 응답이 필요합니다.
- 검증: Windows→Ubuntu 및 역방향 후보 전환, 성공 후보의 재부팅 후 우선순위,
  일반 종료/타임아웃 무시, 중복 오류, 두 후보 소진, 수동 재시도 및 키 보존 테스트 통과.
  BLE 이벤트 테스트에서 인증 전 이름 불필요, 인증 후 이름 실패에도 연결 유지 확인.
  ESP-IDF v6.1 빌드 통과. 실제 PC의 인증 실패 후 재접속 정책은 하드웨어 확인이 필요합니다.
- 확인 로그: `trying saved Ubuntu/Windows key` → 실패 시 다음 재접속의 다른 후보 →
  `bonded and encrypted`를 확인합니다. PC가 일반 종료 코드만 보내는 경우에는 후보를
  자동 전환하지 않으므로 실패 직전부터 로그가 필요합니다.
